## 三个核心判断（开门见山）

1. **三代模式的演进根因只有一个：决策权从开发者搬到大模型**——从编译期决策+运行时执行，变成运行时决策+运行时执行，GoF 23 模式因此集体"失重"。
2. **三代是叠加不是替代**：对象协作 → 服务协作 → 模型协作，问题升级，旧模式被"抬高一层次"，而不是被推翻。
3. **Agent 架构 = 在不确定性之下设计有界资源的分配**：模型负责花钱，Harness 负责管账。

## 开篇三句话

| 代 | 解决的问题 |
|---|---|
| GoF | 代码怎么**组织** |
| 分布式 | 服务怎么**存活** |
| Agent | 模型怎么被**约束地行动** |

## 四大 GoF 模式断裂（最核心的对照表）

| 你以为还在用 | 实际断裂原因 | Agent 时代接替者 |
|---|---|---|
| Singleton | 状态不再全局共享：上下文有 token 上限、每轮重置 | MemoryArchitecture（4 层记忆） |
| Factory | 动作空间编译期开放：MCP 运行时动态发现工具 | SemanticToolRouter（语义工具路由） |
| Observer | 同步推送会自爆：DOM/logstream 全推 token 烧完 | ActivePerception（主动感知，自己决定看什么） |
| Strategy | 人不再选策略：LLM 在 reason() 里每步自己挑 | Strategy 搬进了 Agent 脑子里 |

## GoF 假设 vs 分布式现实

```
共享内存   → 网络分区（看不到彼此状态）
同步调用   → 异步消息（等不到响应可能就是丢了）
单点失败   → 部分失败（30% 节点挂了系统还要工作）
确定性     → CAP 三选二（C/A/P 不能全要）
```

> 9 个分布式模式的共同特征：**把"不确定性"当首要关注点**。推荐书：《Release It!》（地位类似 GoF 之于 OO 时代）。

## 三种不确定性（Agent 时代的新前提）

| 不确定性 | 一句话 |
|---|---|
| 输出不确定 | 同一 prompt 跑十次，可能十种答案——retry 幂等假设失效，熔断/幂等键要重装一遍 |
| 行为不确定 | 调不调工具、先调哪个、循环多长，都不是设计阶段能预测的 |
| 环境不确定 | 页面布局明天会变、Codebase 被同事改过——世界不会等 Agent |

> 反直觉：try-catch + retry + timeout 治不了 Agent 系统。**必须把不确定性当默认运行条件**，默认会漂、会偏、会失控，在这个前提下设计结构。

## Harness：真正的新地基

**工程师定义的范围扩展了**——除了"系统做什么"，还要定义：

```
模型在什么上下文思考 / 能看到什么信息 / 能调哪些工具
什么条件下必须停 / 错了怎么拉回来 / 做过什么谁留痕谁审计
─────────────────────────────────────
这一整层不是 prompt，这一整层就是 Harness
```

| 概念 | 一句话 |
|---|---|
| 花钱 | token、context、工具调用、wall-clock、用户信任、不可逆风险——都是钱 |
| 管账 | Harness 不创造智能，只约束智能的开销与后果 |
| 最高杠杆 | 改 prompt = 让它"这次别犯"；改 Harness = 让它"以后都别犯" |
| 分界线 | 调 prompt 是局部修补；做 Harness 是把局部错误上升为系统纪律 |

## 双轴正交框架（这一代的 GoF 词汇）

```
轴一：认知功能 → 感知 记忆 推理 行动 反思 协作 治理
      （资源花在哪里）
轴二：执行拓扑 → 链式 路由 并行 编排 循环 层级
      （资源怎么花出去）

28 个新模式 = 花什么资源 × 怎么花
```

## 留言区最狠的三条（作者回复精华）

- **ELK 日志挤爆上下文**：规则要从"劝模型"升级成"绕不过去的结构"，软到硬五级：AGENTS.md → P0 区重注入 → 返回硬上限 → pre-tool-use hook → 主 agent 根本不暴露该工具。**规则变成架构的一部分，就不需要模型记得遵守。**
- **同步机制四层**：懒拉取（冷数据）/ 定时刷新（温数据）/ 事件驱动失效（热数据）/ 混合分层——生产系统都是混合分层。
- **OODA 环彩蛋**：观察者→单例→策略→工厂 恰好对应 Observe→Orient→Decide→Act——对象系统里的运行闭环，而 OODA 正是 Harness 核心。

## 收尾纲领

> **GoF 教我们组织代码；分布式教我们驯服网络；Agent 时代逼我们驯服模型的运行时决策——驯服靠的就是 Harness 工程。**
> 模型注定会犯错；Harness 的使命是：在模型注定会犯错的前提下，依然让系统持续产生正确结果。
