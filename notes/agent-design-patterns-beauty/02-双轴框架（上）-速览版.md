## 三个核心判断（开门见山）

1. **Agent 设计模式回答的不是"代码长什么样"，而是"一个不确定的模型，在有限资源里，把注意力、记忆、推理、工具、权限和责任分别放到哪里"**——所以模式清单不够用，需要坐标系。
2. **纵轴不是 7 个名词，是 7 种资源预算**：感知=注意力、记忆=连续性、推理=不确定性、行动=不可逆性、反思=校正、协作=分工、治理=信任。缺哪一脉，就在哪类资源上失控。
3. **横轴不是流程图轴，是错误传播路径轴（failure propagation axis）**：你选择了拓扑，就是在选择错误如何移动。

## 双轴一图流

```
                纵轴 What：认知功能（Agent 在消耗哪种资源）
                ┌────────────────────────────────────┐
                │ 内圈·核心认知：感知 记忆 推理 行动    │ → 让 Agent 能用
                │ 中圈·元认知　：反思                  │ → 让 Agent 可靠
                │ 外圈·系统智能：协作 治理             │ → 让 Agent 能上线
                └────────────────────────────────────┘
横轴 How：执行拓扑（资源/错误怎么流）
Chain 传 | Route 选 | Parallel 撒 | Orchestrate 协 | Loop 转 | Hierarchy 分

What × How 交叉 → Why（为什么这个场景需要这个模式）→ 每个模式获得唯一坐标
```

> 没有坐标："我们用了一个 agent workflow" ≈ 零信息量。
> 有了坐标："推理 × 循环的迭代假设 + 治理 × 路由的审批门控" → 可进入工程评审。

## 业界分类：都对，但都只是"三视图"

| 分类者 | 在数什么 | 共同盲区 |
|---|---|---|
| Lilian Weng | 模块 | ❌ 感知：生产系统最先死的是 input（注意力预算第一道闸） |
| Anthropic | Workflow | ❌ 反思：Reasoning 是生成方向，Reflection 是纠偏方向，必须独立成脉 |
| Andrew Ng | 常见 Pattern | ❌ 治理：Demo 可以没有治理，工程不能——强能力没有边界，就是强事故 |
| Chip Huyen | 工程角色 | 根因：太关注模型"里面"，太少讨论模型"周围"→ Model spends, harness budgets |

## 纵轴七脉 = 七种资源预算（一行一概念）

| 脉 | 预算 | 失控表现 |
|---|---|---|
| 感知 | 注意力 | "看到太多 = 什么都没看见"；上下文分诊如急诊分诊 |
| 记忆 | 连续性 | 每次像初见（没成长）；啥都永久保存（被旧账拖死） |
| 推理 | 不确定性 | 所有问题都"深度思考"是浪费；慢思考留给难任务 |
| 行动 | 不可逆性 | 推理错可重答，行动错可能不可补偿；风险分级 |
| 反思 | 校正 | Self-Critic 自我合理化；必须配终止条件 + 评价标准 + Ground Truth |
| 协作 | 分工 | 价值=专业化+隔离；"大家都知道一切 → 都被噪声淹没" |
| 治理 | 信任 | 是运行时机制不是合规文档；可见、可停、可回放、可解释 |

**建设顺序（大量团队死因是顺序反了）**：先内圈跑顺 → 再加反思 → 最后协作治理。"错误涌现，不是智能涌现。"可以暂时不实现某一脉，**但不能假装它不存在**。

## 横轴六式 = 六种错误传播方式（一行一概念）

| 式 | 口诀 | 要点 | 错误怎么走 |
|---|---|---|---|
| Chain | 传 | 可预测，但链越长中间格式越重要 | 级联：下游不纠错，把错包装得更漂亮 |
| Route | 选 | 核心是分类器质量；降平均成本和风险 | 分派：路由错了后面再强也难救 |
| Parallel | 撒 | 关键在 merge 不在 fan-out | 聚合：没有好的 merge = 把噪声并行化 |
| Orchestrate | 协 | 中心拆解+汇总（Plan-and-Execute） | 分解：失败模式是拆错边界 |
| Loop | 转 | 核心是停止条件、评估信号、改动幅度 | 复合：最迷人也最危险，"越改越忙越忙越偏" |
| Hierarchy | 分 | 多层责任分解（≠一层中心的 Orchestrate） | 放大或隔离：隔离没做好就向上雪崩 |

## 你以为 vs 实际

| 你以为 | 实际 |
|---|---|
| 感知是前处理的小步骤 | 是注意力预算的**第一道闸**，生产系统最先死的就是 input |
| Reflection 只是 Reasoning 的技巧 | 独立一脉：生成方向 vs 纠偏方向，是把"一次性回答"推进到"可迭代改进"的关键机制 |
| 治理是上线前补的合规文档 | 与工具调用**同一层**的运行时机制（审批门控、爆炸半径、审计、trace） |
| Hierarchy = Orchestrate | Orchestrate 是**一层**中心编排多个 worker；Hierarchy 是**多层**责任分解 |
| 六式是流程图画法 | 是错误的传播路径轴——选拓扑 = 选错误怎么移动 |

## 留言区最狠的三条（作者回复精华）

- **Route vs Orchestrate**：路由=从固定菜单挑一个，决策一次就退场；编排=菜单临时生成，中心全程在场收回结果做综合（作者贴伪代码对比）。
- **90% 定律**：Agent 系统最终失败，90% 不是模型不会推理，而是**错误在系统里扩散了**——所以设计的本质是约束。
- **Agent 的推理 = LLM 的推理 + Harness 的推理**：LLM 推理是黑箱；Harness 推理是人为编排（对抗-批判、循环反复、思维链分层次），逐渐被 LLM 吃掉但吃不全。

## 收尾纲领

> **纵七脉定资源得失，横六式断错误路径。双轴既立，Agent 工程评析才真正入微。**
> 目录只能告诉你有哪些模式；坐标系才能告诉你：为什么这个模式在这里、那个模式不该在那里、新模式如何进入同一套工程语言。
