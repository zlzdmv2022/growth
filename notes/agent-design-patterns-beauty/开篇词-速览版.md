## 🎯 三个核心判断

1. **缺的不是工具，是设计语言** —— Claude Code、MCP、LangGraph 大家都能接，demo 都能跑；Agent 出问题时只能归因"模型不够强、prompt 要调"，粒度太粗。
2. **Agent 的价值 = 沉淀经验的能力**，而非今天有多聪明。不记坑、不沉淀 Skill 的 Agent 只是"每天重新入职的聪明新人"。
3. **范式变化**：传统软件控制流写死在代码里；Agent 系统的控制流由模型**运行时决定**。工程师的工作从"写逻辑"变成**设计决策边界**。

> **金句：The model spends; the harness budgets.**（模型负责花，Harness 负责预算）
> **底层定义：Agent 架构 = 不确定性下的有限资源分配**

## ⚠️ 资源悖论（记牢这张表）

| 你以为 | 实际 |
|---|---|
| 200K token → 更聪明 | 可能只是更乱 |
| 40 个工具 → 更强 | 混乱迷失 |
| 8 个 SubAgent → 更全面 | 8 份无法合并的噪声 |
| 完全自主 → 更像专家 | 更快把错误扩散出去 |

## 📐 双轴正交框架（全课程的坐标系）

```
            Y 轴 · 认知功能（WHAT · 7 个）
            感知 → 记忆 → 推理 → 行动 → 反思 → 协作 → 治理
            （入口）                          （闸门）
                    ┼─────────────────
      X 轴 · 执行拓扑（HOW · 6 种）
      链式 / 并行 / 路由 / 循环 / 层级 / 编排
```

- 讨论任何 Agent 问题：**先问解决哪类认知问题，再问能力怎么编排**
- 7 个认知功能形成闭环：感知是入口、治理是闸门、记忆跨时间、协作跨空间、推理做决策、反思审计决策

## 🧩 28 个模式 = 稀缺资源分配表

| 模式 | 分配什么资源 |
|---|---|
| 上下文分诊 | 注意力（谁能进入有限窗口） |
| 语义压缩 | 有损压缩（错误堆栈永远不能压） |
| 工具调度 | 工具/风险/状态刷新 |
| 生成-批评 | 用 critic 约束 generator（找 bug 比写无 bug 代码容易） |
| 经验回放 | 把经验资产变成下次任务的上下文 |
| 审批门控 | 信任分级（什么自动做、什么必须人看） |

## 📚 九模块路线图

| 模块 | 一句话 |
|---|---|
| 01 范式觉醒 | GoF 不够用了 → 双轴框架 + 逆向五步法 |
| 02 感知 | token 花在刀刃上 |
| 03 记忆 | 组织记忆系统（短期+长期+失败+进度） |
| 04 推理 | 脑力分级，成本花在需要搜索的地方 |
| 05 行动 | 每次工具调用都带风险和副作用 |
| 06 反思 | 成长性 = 失败日记 + 技能包 + 自愈 |
| 07 协作 | 多 Agent = 上下文隔离 + 角色分工 + 结果聚合 |
| 08 治理 | 越能干越需要治理（审批/爆炸半径/回放） |
| 09 组合 | 模式选型卡 + 六步选型法 |

## 🏆 三种能力（学习目标）

1. **看穿系统**：不稳定时能精准归因（上下文？记忆？档位？工具？反思？治理？）
2. **组合模式**：模式是零件，组合才是架构（金融研报 = 多模态+RAG+路由+批评+审批+可观测）
3. **设计成长机制**：从第 1 天的聪明 → 第 365 天的老练

## 🌟 收尾纲领

> **记失败、存经验，价值始聚**
> **知进退、懂组合，系统方生**

软件工程的稳定主题：**把偶然成功变成可重复成功** —— 找出"刚好成功"背后的结构，命名它、约束它、复用它、组合它。
